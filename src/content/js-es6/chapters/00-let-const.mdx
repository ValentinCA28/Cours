## Pourquoi `let` et `const` ?

Avant ES6 (2015), JavaScript ne disposait que d'un seul moyen de déclarer une variable : le mot-clé <InlineCode>var</InlineCode>. Ce dernier souffre de plusieurs défauts qui rendent le code difficile à raisonner :

- **Scope de fonction uniquement** : une variable déclarée avec <InlineCode>var</InlineCode> n'est pas limitée au bloc <InlineCode>{"{ ... }"}</InlineCode> dans lequel elle apparaît.
- **Hoisting silencieux** : la déclaration est "remontée" en haut de la fonction, mais sa valeur reste <InlineCode>undefined</InlineCode> jusqu'à l'exécution réelle de la ligne.
- **Redéclaration autorisée** : tu peux redéclarer la même variable plusieurs fois sans erreur, ce qui masque les bugs.

ES6 introduit deux nouveaux mots-clés : <InlineCode>let</InlineCode> et <InlineCode>const</InlineCode>. Ils corrigent ces problèmes et deviennent le standard moderne.

## Comparaison rapide

| Caractéristique | `var` | `let` | `const` |
|---|---|---|---|
| Scope | Fonction | Bloc | Bloc |
| Hoisting | Oui (undefined) | Oui (TDZ) | Oui (TDZ) |
| Redéclaration | Autorisée | Interdite | Interdite |
| Réassignation | Autorisée | Autorisée | Interdite |
| Ajouté à `window` (global) | Oui | Non | Non |

## Le scope de bloc

Avec <InlineCode>var</InlineCode>, une variable déclarée dans un <InlineCode>if</InlineCode> ou une boucle **fuit** à l'extérieur du bloc :

```js
// var : la variable fuit du bloc
if (true) {
  var message = "Hello";
}
console.log(message); // "Hello" — accessible !

// let : la variable est confinée au bloc
if (true) {
  let greeting = "Bonjour";
}
console.log(greeting); // ReferenceError : greeting is not defined
```

Le piège classique du <InlineCode>var</InlineCode> dans une boucle :

```js
// Avec var : i fuit, le setTimeout voit la valeur finale
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Affiche : 3, 3, 3

// Avec let : chaque itération a son propre i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Affiche : 0, 1, 2
```

## `const` : référence figée, pas valeur figée

Une variable déclarée avec <InlineCode>const</InlineCode> ne peut pas être **réassignée**. Mais attention : si la valeur est un objet ou un tableau, son **contenu** reste mutable.

```js
const user = { name: "Alice", age: 25 };

// Mutation autorisée : on modifie une propriété
user.age = 26;
user.email = "alice@example.com";
console.log(user); // { name: "Alice", age: 26, email: "..." }

// Réassignation interdite : on essaie de remplacer l'objet
user = { name: "Bob" }; // TypeError : Assignment to constant variable
```

Même logique pour les tableaux :

```js
const numbers = [1, 2, 3];

numbers.push(4);     // OK : on mute le tableau
numbers[0] = 99;     // OK : on mute le tableau
console.log(numbers); // [99, 2, 3, 4]

numbers = [];         // TypeError : on essaie de réassigner
```

<Callout variant="info" title="Astuce mentale">
  <InlineCode>const</InlineCode> verrouille la **boîte**, pas le **contenu**. La variable pointe toujours vers le même objet, mais cet objet peut être modifié. Pour figer aussi le contenu, utilise <InlineCode>Object.freeze()</InlineCode>.
</Callout>

## La Temporal Dead Zone (TDZ)

Les variables <InlineCode>let</InlineCode> et <InlineCode>const</InlineCode> sont aussi "hoistées", mais contrairement à <InlineCode>var</InlineCode>, elles ne sont **pas initialisées** à <InlineCode>undefined</InlineCode>. Elles existent dans une zone temporelle morte (TDZ) jusqu'à leur déclaration effective :

```js
// var : hoisting classique, undefined avant la déclaration
console.log(a); // undefined
var a = 1;

// let : TDZ, accès interdit avant la déclaration
console.log(b); // ReferenceError : Cannot access 'b' before initialization
let b = 2;
```

La TDZ t'oblige à déclarer tes variables **avant** de les utiliser, ce qui rend le code plus prévisible.

## Quel mot-clé choisir ?

<Callout variant="info" title="Bonne pratique">
  Utilise <InlineCode>const</InlineCode> par défaut pour toutes tes variables. Passe à <InlineCode>let</InlineCode> uniquement quand tu sais que tu vas devoir la réassigner (compteur, accumulation, swap...). N'utilise plus <InlineCode>var</InlineCode> dans du code moderne — il n'a aucun avantage sur ses successeurs.
</Callout>

Cette règle simple a deux bénéfices :

1. **Lisibilité** : un <InlineCode>let</InlineCode> dans le code signale immédiatement *"cette variable va changer"*.
2. **Sécurité** : tu évites les réassignations accidentelles, qui sont une source classique de bugs.
